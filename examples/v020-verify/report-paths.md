## Остаточные риски

1. **`--for` в read не валидируется (комментируется в п.1, дублирую как риск).** Единственное имя, попадающее в путь без NAME_RE. Эксплойт требует запуска команды с `--for`, содержащим `..` — то есть атакующий уже должен иметь право запускать team.py. Угроза не удалённая, но изоляция mailbox'ов агентов друг от друга (`read` чужого ящика, подмена содержимого через write) нарушается. Фикс: одна строка check_name.

2. **Валидация только на входе, состояние считается доверенным.** `save_mailbox` (team.py:129-133) строит путь из `t["assignee"]` без повторной проверки. Если tasks.json правят руками (минуя init/claim), письмо verify fail уйдёт по пути с `..`. Риск принятый (доверенная зона `.agent-teams/`), но стоит помнить: NAME_RE защищивает ingress, не хранилище.

3. **`--by` в tokens не валидируется.** В путь не попадает (owner лока и actor события — JSON-контент), но это дыра в правиле «каждое имя через check_name» и лёгкий канал мусора в events.jsonl.

4. **NAME_RE не фильтрует зарезервированные имена Windows.** `CON`, `NUL`, `AUX`, `COM1`-`COM9`, `LPT1`-`LPT9` проходят шаблон; `inbox/CON.json` на Windows разрешается в устройство, а не файл (behaviour зависит от API). Не traversal, но источник трудноотлаживаемых сбоев на целевой для проекта платформе. Аналогично `--team CON`.

5. **`deps` при init не прогоняются через check_name** (team.py:157). В пути не участвуют (только сравнение в find_task, team.py:184), максимум — отказ «задача не найдена». Консистентность страдает, безопасность нет.

6. **`files_read`/`files_write` — декларация без контроля.** Движок нигде не ограничивает запись агента списком `files_write`; этот контракт держится только на дисциплине процесса. Для аудита safety это значит: изоляция записи между агентами не механическая.

7. **Попутное наблюдение вне линзы (для aud-races):** `cmd_tokens` читает и мутирует tasks.json до взятия лока (чтение team.py:258-259, мутация 261-262, лок только на записи team.py:263-264) — классическое окно lost update. Отнесено к чужому чеклисту, здесь только фиксируется.

8. **`--tasks` в init — произвольный путь чтения по дизайну** (team.py:141). Считаю ожидаемым поведением, не риском; отмечено для полноты.
